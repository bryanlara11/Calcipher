## B. Root cause analysis

### Confirmed code defects and reliability gaps

- There was no supported local image/caption import command, so the usable data path depended
  on successful live scraping or manually constructing internal stage files.
- Missing/corrupt sessions escaped before the scraper's guarded listing loop. Session identity
  was not checked. The download path wrote completion metadata without checking image count or
  decodability. Instaloader can suppress some thumbnail errors; checking the files independently
  prevents falsely completed posts. Carousel filenames sorted lexically (`1,10,2`) and prefix
  matching could include images belonging to a different shortcode.
- Carousel OCR was concatenated into one parser stream. Name, macro and serving state could
  cross slide boundaries. Conflicting repeated item values could be silently discarded.
- OCR cache JSON corruption could stop a stage; parse read cached text without checking that
  it still matched image bytes. Partial OCR could create a review row and permanently prevent
  later slides being appended because the post was already considered reviewed.
- The parser/read loader used the invented default `1 serving` when a source supplied none.
  It dropped explicit zero-calorie values and mishandled thousands-formatted calorie figures.
  Canonical macro text rounded away supported decimal precision.
- Ordinary parsed rows started at `action=load`, weakening the intended review gate. A load
  committed the catalog before branch rematching, so a later rematch failure left partial effects.
- Prices/budgets were absent across schema, API, parser and SQL. A budget request could not be
  enforced. The prior LLM guard checked only calorie numbers; invented prices/macros/servings or
  assigning a real number to the wrong meal could pass that guard.

### External restrictions: evidence versus inference

The repository's historical notes report 401/429 interruptions, but no original live Instagram
logs or authorized source dataset were available here. This audit did **not** reproduce a live
Instagram refusal or successfully collect a live post. A deliberately nonexistent session file
was tested through the CLI and produced a recoverable `session_error` with zero collected posts.
Listing/download authentication and 401/429 behavior was tested with mocked exceptions.

401 may reflect an expired/missing login or Instagram's access enforcement; 429 indicates rate
limiting. These are plausible causes of the historical interruption, not a diagnosis of the
owner's actual session or this network. Instaloader documents request-budget assumptions and
warns that rapid restarting can worsen 429s. No proxy, session borrowing, CAPTCHA automation,
identity rotation or other evasion was added.
[Instaloader troubleshooting](https://instaloader.github.io/troubleshooting.html).

The official Instagram API is conditional on supported account types and app authorization;
the source owner's account permissions were not established. Owner-supplied originals or an
authorized export are therefore the recommended acquisition path, followed by the new local
import workflow. See [Meta's Instagram Login API documentation](https://developers.facebook.com/documentation/instagram-platform/instagram-api-with-instagram-login).

- The persistent development catalog is empty; synthetic audit fixtures are confined to test data.
  Default demo seeds are illustrative, never evidence for the academic dataset.
- Real OCR remains imperfect on small text/complex columns; original-resolution sources and
  human review are required. A whole-slide parser is not a general nutrition-table layout engine.
- Previously imported legacy records may contain the old inferred `1 serving`. Those cannot be
  safely distinguished from real one-serving evidence, so they were not automatically rewritten.
  Existing data needs a source-based re-audit. Changing item identity does not delete an old row.
- Price evidence is item/serving source evidence, not guaranteed live branch-specific pricing.
  Old rows have null prices and are excluded from budgets. Nutrition-only searches may still
  include unverified records with explicit warnings, preserving existing prototype behavior.
- Mixed embedding spaces still require the existing re-embedding workflow; startup/health warn
  about stale rows. Hash test results do not prove production semantic relevance.
- Docker was not built or exercised; Compose lacks persistent ingestion data/source mounts.
  pg_trgm is absent from pgserver; its optional legacy index is skipped.
- Existing Places result/rating limits, brand heuristics, per-process rate limiting, and lack of
  Alembic remain. No unrelated architecture rewrite was performed.
- `npm audit` reports **three dependency entries: esbuild moderate, postcss high, vite high**.
  The build passes, but the dependencies need a focused security update before public deployment.
